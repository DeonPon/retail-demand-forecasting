# Вимоги до програмної системи

## Функціональні вимоги
- авторизація користувача;
- перегляд dashboard з KPI;
- перегляд каталогу товарів;
- прогнозування попиту по товару;
- перегляд рекомендацій закупівель;
- перегляд метрик моделі;
- імпорт CSV;
- перенавчання моделі;
- надання REST API.

## Нефункціональні вимоги
- зрозумілий інтерфейс українською мовою;
- адаптивність під типові екрани ноутбука, планшета та телефона;
- стабільна робота без зовнішніх CDN;
- помірне споживання ресурсів для Render;
- швидке завантаження dashboard без зайвих обчислень на кожному рендері.

## Вимоги до безпеки
- вхід лише для авторизованого користувача;
- зберігання пароля у вигляді хешу;
- сесійний контроль доступу до захищених сторінок;
- відсутність секретних ключів у коді;
- використання змінних середовища для production.

## Вимоги до даних
- CSV має містити обов’язкові колонки;
- дата повинна коректно парситися;
- кількісні поля повинні мати числовий формат;
- система має коректно обробляти додаткові колонки;
- некоректний CSV не повинен ламати систему.

## Вимоги до інтерфейсу
- читабельні KPI-картки;
- таблиці з фільтрацією та сортуванням;
- графіки фактичних продажів і прогнозу;
- порожні стани та повідомлення про помилки;
- пояснення прогнозу простими словами.

## Вимоги до продуктивності
- не виконувати повторне тренування моделі під час звичайного перегляду сторінок;
- використовувати кешування для читання даних і read-only прогнозів;
- виконувати важкі операції лише при імпорті або retrain;
- не записувати в базу даних під час звичайного рендеру dashboard.

## Вимоги до надійності
- система повинна запускатися локально і на Render;
- API має повертати зрозумілий JSON;
- у разі помилки потрібно показувати зрозуміле повідомлення українською;
- за відсутності моделі або даних інтерфейс має показувати fallback-стан, а не порожній екран.
