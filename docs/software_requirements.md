# Вимоги до програмної системи

## Функціональні вимоги

- авторизація менеджера;
- перегляд dashboard;
- перегляд каталогу товарів;
- завантаження CSV-файлу;
- перенавчання ML-моделі;
- отримання прогнозу попиту;
- отримання рекомендації закупівлі;
- перегляд метрик якості моделі;
- доступ до REST API.

## Нефункціональні вимоги

- простота розгортання;
- зрозуміла структура коду;
- адаптивний web-інтерфейс;
- відокремлення backend, ML-модулів, бази даних і документації;
- можливість публічного деплою.

## Вимоги до безпеки

- session-based авторизація;
- хешування пароля;
- захист dashboard-сторінок;
- відсутність приватних даних у репозиторії;
- використання `SECRET_KEY` із середовища для production.

Демонстраційний логін `admin` і пароль `admin123` використовуються тільки для дипломного прототипу.

## Вимоги до даних

CSV має містити: `date`, `product_id`, `product_name`, `category`, `sales_quantity`, `price`, `stock_quantity`, `promo`, `holiday`, `supplier_delay_days`.

## Вимоги до інтерфейсу

Інтерфейс має бути українською мовою, містити dashboard, графік продажів і прогнозу, таблиці товарів, рекомендації закупівель, сторінку метрик і сторінку опису системи.

## Вимоги до продуктивності

Прототип має швидко обробляти демонстраційний CSV і будувати прогноз для кількох товарів. Для production-версії потрібна оптимізація під більші масиви даних.

## Вимоги до надійності

Система має обробляти неправильний CSV, відсутність товару, відсутність моделі та недостатність даних для прогнозування.
