# Початкові формулювання для дипломної роботи

## Мета дипломної роботи

Метою дипломної роботи є розробка програмного прототипу інтелектуальної системи прогнозування попиту на товари в ритейлі, яка аналізує історичні дані продажів, формує ознаки для машинного навчання, навчає прогнозну модель і надає менеджеру прогноз попиту та рекомендації щодо закупівлі товарів.

## Об'єкт дослідження

Об'єктом дослідження є бізнес-процеси прогнозування попиту в ритейлі та управління товарними запасами.

## Предмет дослідження

Предметом дослідження є методи попередньої обробки даних, feature engineering та алгоритми машинного навчання для прогнозування попиту на товари.

## Основні задачі дипломної

1. Проаналізувати предметну область прогнозування попиту в ритейлі.
2. Визначити вимоги до вхідних даних про продажі, акції, ціни та залишки.
3. Реалізувати підготовку даних і створення ознак: календарні ознаки, сезонність, лаги продажів, рухомі середні та ознаку акції.
4. Навчити базову модель машинного навчання для прогнозування попиту.
5. Оцінити якість прогнозування за метриками MAE, RMSE та MAPE.
6. Розробити backend API для отримання прогнозів, оновлення даних і рекомендацій закупівлі.
7. Створити простий web-інтерфейс менеджера з таблицею товарів, прогнозом, рекомендацією та графіком.

## Очікуваний результат

Очікуваним результатом є робочий дипломний прототип системи, який дозволяє завантажувати або використовувати CSV-дані продажів, навчати модель прогнозування попиту, переглядати прогноз у web-інтерфейсі та отримувати рекомендацію щодо кількості товару для закупівлі.

## Структура майбутньої системи

Система складається з таких модулів:

- модуль даних: зберігання CSV і завантаження історії продажів;
- модуль попередньої обробки: очищення, сортування, перевірка типів даних;
- модуль feature engineering: календарні ознаки, сезонність, лаги, рухомі середні, ознака акції;
- модуль навчання моделі: тренування, оцінювання, збереження моделі;
- модуль прогнозування: побудова прогнозу на наступні дні;
- модуль рекомендацій: розрахунок рекомендованої кількості закупівлі;
- backend/API: endpoint-и для прогнозів, оновлення даних і рекомендацій;
- web-інтерфейс: сторінка менеджера з таблицею, прогнозами та графіком.
