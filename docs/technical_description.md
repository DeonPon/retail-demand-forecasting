# Технічний опис системи

## Призначення
Система призначена для прогнозування попиту на товари та підтримки управлінських рішень у ритейлі.

## Архітектура
Система побудована як web-застосунок на Flask з поділом на кілька логічних модулів:
- web-рівень і шаблони інтерфейсу;
- модуль підготовки та імпорту даних;
- ML-модуль прогнозування;
- SQLite база даних;
- REST API.

## Backend
Flask обслуговує:
- сторінки `Огляд`, `Дані`, `Прогноз`, `Модель`, `Про систему`;
- API для прогнозів, імпорту, метрик і системної інформації;
- локальний рендер графіків без зовнішніх CDN.

## Frontend
Інтерфейс реалізовано через HTML-шаблони, власний CSS і локальний JavaScript:
- строгий аналітичний стиль;
- KPI-картки;
- таблиці набору даних;
- локальні Canvas-графіки;
- адаптивність під ноутбук, планшет і телефон;
- fallback-стани, якщо графіки чи API тимчасово недоступні.

## ML-модуль
ML-модуль:
1. завантажує історичні продажі;
2. формує ознаки;
3. навчає кілька регресійних моделей;
4. обирає найкращу за MAPE;
5. зберігає модель у `models/demand_model.joblib`;
6. зберігає метрики та важливість ознак у `models/metrics.json`.

## Використані моделі
- `RandomForestRegressor`
- `GradientBoostingRegressor`
- `ExtraTreesRegressor`

## База даних
SQLite використовується для демонстрації структури реальної інформаційної системи. У ній зберігаються:
- користувачі;
- товари;
- продажі;
- прогнози;
- метрики моделей;
- історія імпортів.

## API
Основні endpoints:
- `GET /health`
- `GET /api/products`
- `GET /api/products/<id>`
- `GET /api/categories`
- `GET /api/forecast/<product_id>?days=14`
- `GET /api/recommendation/<product_id>?days=14`
- `GET /api/recommendations?days=14`
- `GET /api/metrics`
- `GET /api/feature-importance`
- `POST /api/upload`
- `POST /api/retrain`
- `GET /api/imports`

## Санкціонований доступ
У демонстраційній версії інтерфейс відкритий для зручності захисту. Архітектура дозволяє надалі додати авторизацію користувачів, сесії та розмежування ролей.

## Логіка прогнозування
Прогноз враховує:
- історичні продажі;
- лаги та ковзні середні;
- день тижня й вихідні;
- місяць і сезонність;
- акції та святкові дні;
- ціну й її зміну;
- залишок на складі;
- затримку постачальника;
- категорію товару.

## Практичне використання прогнозу
Результати прогнозування можуть використовуватися для попереднього планування запасів, аналізу сезонності, оцінки тенденцій і підтримки управлінських рішень у ритейлі.
