# Технічний опис системи

## Загальна характеристика
Retail Demand Sense — Flask/Python застосунок для прогнозування попиту на товари ритейлу. Система працює локально, використовує SQLite для збереження даних, CSV для імпорту історичних продажів і scikit-learn для навчання моделей машинного навчання.

## Flask backend
Backend реалізовано у `app/app.py`. Він відповідає за:
- web-сторінки `Огляд`, `Дані`, `Прогноз`, `Модель`, `Про систему`;
- API endpoints для продуктів, прогнозу, метрик, імпорту й перевірки стану;
- обробку CSV-завантаження;
- передачу підготовлених даних у Jinja2-шаблони;
- швидке відкриття сторінок без повторного навчання моделі під час перегляду.

## SQLite database
SQLite використовується як локальна база даних дипломного прототипу. Основна логіка роботи з базою винесена в `src/database.py`. У базі зберігаються:
- товари;
- історичні продажі;
- сформовані прогнози;
- метрики моделей;
- журнал імпортів;
- службова інформація для роботи системи.

Структура бази описана в `docs/database_schema.sql` і `docs/database_description.md`.

## CSV import
CSV-імпорт дозволяє завантажити історичні записи продажів. Файл містить дату, товар, категорію, кількість продажів, ціну, акції, свята, залишки та допоміжні характеристики. Після завантаження система перевіряє структуру, очищає дані та імпортує їх у SQLite.

## Data preprocessing
Модуль `src/data_processing.py` відповідає за:
- перевірку обов’язкових колонок;
- перетворення дати у коректний формат;
- нормалізацію числових полів;
- сортування записів за товаром і датою;
- підготовку даних до навчання моделі.

## Feature engineering
Для моделі формуються ознаки, які описують поведінку попиту:
- день тижня, місяць, квартал;
- вихідний день;
- лаги продажів;
- ковзні середні;
- акційний період;
- ціна та зміна ціни;
- категорія товару;
- базовий попит і сезонність.

## ML training
Навчання моделей виконується в `src/train_model.py`. Дані поділяються на навчальну та тестову вибірки. Система навчає кілька регресійних моделей і порівнює їх за метриками якості.

## Model selection
Порівнюються:
- `RandomForestRegressor`;
- `GradientBoostingRegressor`;
- `ExtraTreesRegressor`.

Основною обирається модель з найнижчим значенням MAPE на тестовій вибірці. У поточній реалізації це `ExtraTreesRegressor`.

## Forecast generation
Прогноз формується в `src/predict.py`. Для вибраного товару система бере історичні продажі, формує потрібні ознаки для майбутніх дат і покроково прогнозує попит на 7, 14 або 30 днів. Прогнозні значення відображаються після останньої історичної дати, не накладаючись на фактичні продажі.

## Metrics
Для оцінки якості використовуються:
- MAE — середня абсолютна помилка в одиницях товару;
- RMSE — метрика, чутлива до великих помилок;
- MAPE — середня відносна похибка у відсотках.

Менші значення метрик означають точніший прогноз.

## Frontend templates
Інтерфейс побудовано на Jinja2-шаблонах, CSS і локальному JavaScript без важких frontend-бібліотек. Графіки рендеряться через Canvas API. Основні шаблони:
- `dashboard.html` — огляд системи;
- `products.html` — структура даних і CSV-імпорт;
- `forecast.html` — прогноз попиту;
- `metrics.html` — якість моделі;
- `about.html` — опис системи для пояснювальної записки.

## Санкціонований доступ
У поточній демонстраційній версії інтерфейс відкритий для зручності захисту. Архітектура дозволяє надалі додати авторизацію користувачів, сесії та розмежування ролей.
