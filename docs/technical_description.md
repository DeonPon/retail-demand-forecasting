# Технічний опис системи

## Призначення системи

Система призначена для підтримки рішень менеджера ритейлу щодо прогнозування попиту та планування закупівель.

## Архітектура

Архітектура складається з web-рівня Flask, ML-рівня Python, файлового сховища CSV, SQLite-бази даних і frontend dashboard.

## Backend

Backend реалізовано на Flask. Він відповідає за сторінки інтерфейсу, API endpoint-и, завантаження CSV, перенавчання моделі та session-based авторизацію.

## Frontend

Frontend побудований на HTML, CSS, Bootstrap і Chart.js. Інтерфейс містить сторінки Login, Dashboard, Products, Forecast, Recommendations, Model Metrics і About System.

## ML-модуль

ML-модуль використовує Pandas, NumPy та Scikit-learn. Основна модель — `RandomForestRegressor`, оскільки вона добре працює з табличними даними, не потребує складного масштабування ознак і підходить для дипломного прототипу.

## База даних

SQLite використовується як демонстраційна база для опису структур даних і санкціонованого доступу. Таблиці: `users`, `products`, `sales`, `forecasts`, `model_metrics`.

## API

- `GET /api/products`;
- `GET /api/forecast/<product_id>`;
- `GET /api/recommendation/<product_id>`;
- `GET /api/metrics`;
- `POST /api/upload`;
- `POST /api/retrain`;
- `GET /api/system-info`.

## Авторизація

Авторизація реалізована через Flask session. Пароль демо-користувача зберігається у вигляді hash. Для production потрібно додати сильні паролі, HTTPS, CSRF-захист, обмеження спроб входу та безпечне керування ролями.

## Логіка прогнозування

Система завантажує історичні продажі, очищає дані, формує календарні ознаки, лаги, рухомі середні, кодує категорію товару та навчає модель. Прогноз формується ітеративно на наступні дні.

## Логіка рекомендацій

Рекомендована закупівля = прогнозований попит на період + страховий запас - поточний залишок.
