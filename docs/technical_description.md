# Технічний опис системи

## Призначення
Система призначена для прогнозування попиту на товари та підтримки рішень щодо закупівель у ритейлі.

## Архітектура
Система побудована як web-застосунок на Flask з поділом на кілька логічних модулів:
- web-рівень і шаблони інтерфейсу;
- модуль підготовки та імпорту даних;
- ML-модуль прогнозування;
- модуль рекомендацій закупівель;
- SQLite база даних;
- REST API.

## Backend
Flask обслуговує:
- сторінки `Login`, `Dashboard`, `Products`, `Forecast`, `Recommendations`, `Metrics`, `About`;
- API для прогнозів, рекомендацій, імпорту та системної інформації;
- session-based авторизацію;
- локальний рендер графіків без зовнішніх CDN.

## Frontend
Інтерфейс реалізовано через HTML-шаблони, власний CSS і локальний JavaScript:
- світлий CRM/BI стиль;
- KPI-картки;
- таблиці товарів та закупівель;
- локальні Canvas-графіки;
- адаптивність під ноутбук, планшет і телефон;
- fallback-стани, якщо графіки чи API тимчасово недоступні.

## ML-модуль
ML-модуль:
1. завантажує історичні продажі;
2. формує ознаки;
3. навчає кілька регресійних моделей;
4. обирає найкращу за MAPE;
5. зберігає модель у `models/demand_model.joblib`;
6. зберігає метрики та важливість ознак у `models/metrics.json`.

## Використані моделі
- `RandomForestRegressor`
- `GradientBoostingRegressor`
- `ExtraTreesRegressor`

## База даних
SQLite використовується для демонстрації структури реальної інформаційної системи. У ній зберігаються:
- користувачі;
- товари;
- продажі;
- прогнози;
- метрики моделей;
- історія імпортів;
- історія рекомендацій закупівель.

## API
Основні endpoints:
- `GET /health`
- `GET /api/products`
- `GET /api/products/<id>`
- `GET /api/categories`
- `GET /api/forecast/<product_id>?days=14`
- `GET /api/recommendation/<product_id>?days=14`
- `GET /api/recommendations?days=14`
- `GET /api/metrics`
- `GET /api/feature-importance`
- `POST /api/upload`
- `POST /api/retrain`
- `GET /api/imports`

## Авторизація
Система використовує демонстраційну авторизацію:
- сторінка входу;
- пароль зберігається у вигляді хешу;
- доступ до dashboard-сторінок захищений сесією;
- є вихід із системи.

## Логіка прогнозування
Прогноз враховує:
- історичні продажі;
- лаги та ковзні середні;
- день тижня й вихідні;
- місяць і сезонність;
- акції та святкові дні;
- ціну й її зміну;
- залишок на складі;
- затримку постачальника;
- категорію товару.

## Логіка рекомендацій
Рекомендація закупівлі формується за формулою:

`recommended_order = forecast_demand + safety_stock - current_stock`

Страховий запас залежить від:
- середнього попиту;
- нестабільності продажів;
- затримки постачальника;
- категорії товару.
