# Аудит відповідності дипломному завданню

Офіційна тема: «Розробка інтелектуальної системи прогнозування попиту на товари для автоматизації процесів ритейлу».

| Вимога з дипломного завдання | Як реалізовано в проєкті | Де це показано в інтерфейсі або коді | Що можна сказати на захисті |
| --- | --- | --- | --- |
| Прогнозування попиту | Система будує прогноз продажів для вибраного товару на 7, 14 або 30 днів. | Сторінка `Прогноз`, API `/api/forecast/<product_id>`, модуль `src/predict.py`. | Система оцінює очікуваний попит на майбутній період на основі історичних продажів і сформованих ознак. |
| Автоматизація ритейлу | Автоматизовано імпорт даних, підготовку ознак, запуск прогнозу, показ графіка й метрик. | Сторінки `Огляд`, `Дані`, `Прогноз`, `Модель`; routes у `app/app.py`. | Менеджер не рахує прогноз вручну: система збирає дані, обробляє їх і показує аналітичний результат. |
| Управління запасами | Прогноз може використовуватися для попереднього планування запасів без перетворення сайту на складську CRM. | Блок `Практичне використання`, сторінка `Прогноз`, CSV-поле `stock_quantity`. | Прогноз попиту є основою для планування запасів, але система позиціонується саме як прогнозна ML-система. |
| Ціноутворення | Ціна товару зберігається у CSV і використовується як фактор для моделі. | Сторінка `Дані`, колонка `Середня ціна`, feature engineering у `src/data_processing.py`. | Ціна враховується як ознака, оскільки зміна ціни може впливати на попит. |
| Маркетинг | Акційні періоди та календарні фактори враховуються в ознаках моделі. | CSV-поля `promo`, `holiday`, фактори прогнозу в `src/predict.py`. | Система враховує, що попит залежить не лише від минулих продажів, а й від акцій та календарного контексту. |
| Логістика | У даних є затримка постачальника, яка може використовуватись як допоміжна характеристика. | CSV-поле `supplier_delay_days`, опис у документації та preprocessing. | Логістичні фактори можна враховувати як додаткові ознаки для аналізу попиту й планування операцій. |
| Структура даних | Визначено структуру CSV з товарами, категоріями, цінами, кількістю продажів і допоміжними ознаками. | Сторінка `Дані`, `data/README.md`, `docs/database_description.md`. | Вхідні дані структуровані так, щоб їх можна було очищати, зберігати і використовувати для ML-моделі. |
| База даних SQLite | Дані зберігаються локально в SQLite: товари, продажі, імпорти, прогнози, метрики. | `retail_demand.db`, `src/database.py`, `docs/database_schema.sql`, сторінка `Про систему`. | SQLite достатньо для локального дипломного прототипу, а структуру можна перенести на production СУБД. |
| Алгоритм прогнозування | Реалізовано preprocessing, feature engineering, навчання моделей, вибір кращої моделі й покрокове прогнозування. | `src/data_processing.py`, `src/train_model.py`, `src/predict.py`, сторінка `Про систему`. | Алгоритм охоплює весь цикл: від історичних продажів до прогнозу й інтерпретації результату. |
| ML-модель | Порівнюються RandomForestRegressor, GradientBoostingRegressor та ExtraTreesRegressor. | Сторінка `Модель`, `models/metrics.json`, `src/train_model.py`. | Основною обрано ExtraTreesRegressor, бо вона показала найнижчу MAPE на тестовій вибірці. |
| Оцінка точності | Використовуються MAE, RMSE і MAPE. | Сторінка `Модель`, API `/api/metrics`, `models/metrics.json`. | Метрики показують, наскільки прогноз відхиляється від фактичних продажів; менші значення означають кращий результат. |
| Санкціонований доступ | У демонстраційній версії інтерфейс відкритий; архітектура дозволяє додати авторизацію і ролі. | Сторінка `Про систему`, модуль `app/auth`, документація. | Для захисту доступ відкрито, але питання санкціонованого доступу враховано на рівні архітектури. |
| Питання програмної інженерії | Проєкт розділено на backend, ML-модулі, шаблони, static assets, тести й документацію. | Структура `app/`, `src/`, `tests/`, `docs/`, README. | Система має модульну структуру, тести, API endpoints і окрему документацію, що відповідає підходам програмної інженерії. |
| Графічні матеріали | Є графіки історичних продажів і прогнозу, таблиці даних, метрики, структура архітектури. | Сторінки `Огляд`, `Прогноз`, `Модель`, `Про систему`, `docs/screenshots_plan.md`. | Для презентації можна показати об’єкт роботи, проблему, алгоритм, структуру даних і результати розрахунків. |
