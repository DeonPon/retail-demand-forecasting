# Опис алгоритму прогнозування

## Дані

Використовується демонстраційний CSV з історією продажів товарів. Поля: дата, товар, категорія, продажі, ціна, залишок, акція, свято, затримка постачальника.

## Очищення даних

Система перевіряє наявність обов'язкових колонок, приводить дату до формату `datetime`, числові поля до числового типу, видаляє некоректні рядки та сортує дані за товаром і датою.

## Feature Engineering

Створюються такі ознаки:

- `day_of_week` — день тижня;
- `month` — місяць;
- `day_of_month` — день місяця;
- `is_weekend` — чи є день вихідним;
- `promo` — чи діє акція;
- `holiday` — чи є день святковим;
- `lag_1` — продажі за попередній день;
- `lag_7` — продажі за аналогічний день попереднього тижня;
- `rolling_mean_7` — рухоме середнє за 7 днів;
- `rolling_mean_14` — рухоме середнє за 14 днів;
- `stock_quantity` — залишок товару;
- `price` — ціна;
- `supplier_delay_days` — затримка постачальника;
- `category_encoded` — числове кодування категорії товару.

## Навчання моделі

Дані діляться на train/test за часовою ознакою. Для прогнозування використовується `RandomForestRegressor`. Модель обрана тому, що вона добре працює з табличними даними, враховує нелінійні залежності та достатньо проста для деплою.

## Формування прогнозу

Прогноз формується на наступні дні ітеративно. Для кожного наступного дня система створює календарні ознаки, використовує останні продажі як лаги та додає попередній прогноз до історії.

## Рекомендація закупівлі

Формула:

```text
рекомендована закупівля = прогнозований попит + страховий запас - поточний залишок
```

Страховий запас у прототипі становить 15% від прогнозованого попиту.

## Метрики

- MAE — середня помилка в одиницях товару;
- RMSE — помилка, яка сильніше штрафує великі відхилення;
- MAPE — середня відсоткова помилка прогнозу.
